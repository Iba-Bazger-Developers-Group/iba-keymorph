# Смена иконки IBA KeyMorph: почему остаётся старая и как проверить

Разбор для выпуска с новой иконкой (мастера продуктовых иконок появятся в `iba-branding/product-icons/keymorph`).
Названия и идентификаторы за всю историю репозитория не менялись, так что «старых бандлов под другими именами» в
git нет: Windows — `IbaKeyMorph.exe`, AppId `{6B0C7E4B-…}`, папка `…\Programs\IBA KeyMorph`; macOS — `IBA KeyMorph.app`,
bundle id `com.iba.keymorph`, исполняемый `IBAKeyMorph`. Остаются не файлы под другим именем, а кеши и копии,
положенные вручную.

## Windows

| Что | Состояние до | Что сделано (`windows/installer/IbaKeyMorph.iss`) |
|---|---|---|
| Иконка exe | `assets/keymorph.ico`, 16–256 (7 размеров) — уже правильная | без изменений; новая иконка попадает через `assets/keymorph.ico` (`make-icons.ps1`) |
| Ярлык в «Пуске» | без `IconFilename`, иконка берётся из кеша оболочки | `IconFilename`/`IconIndex: 0` указаны явно |
| Ярлыки на рабочем столе, в «Пуске», автозагрузке, закреплённые на панели задач | установщик их не трогал: ярлык, созданный пользователем или старой версией, хранил старую иконку | после установки каждый `.lnk`, запускающий `IbaKeyMorph.exe`, получает иконку exe заново (`RefreshShortcuts`) |
| Автозапуск (`HKCU\…\Run\IBA KeyMorph`) | мог указывать на другую копию (портативная, старая папка) | если значение есть и ведёт не сюда — переписывается на установленный exe; включённость сохраняется |
| Кеш значков Проводника | не сбрасывался | `SHChangeNotify(SHCNE_ASSOCCHANGED)` после установки и удаления |
| `UninstallDisplayIcon` | `{app}\IbaKeyMorph.exe` — верно | без изменений |
| Остатки после удаления | значение автозапуска, записанное переключателем в программе, оставалось | удаляется при деинсталляции |
| Старые файлы в папке программы | exe заменяется на месте, других файлов нет | `[InstallDelete]` убирает `*.old`, `*.tmp` |

Иконка в трее — не панда, а значок текущей раскладки (EN/RU), он рисуется кодом (`TrayIcons.cs`); менять его нужно
отдельно, если новая система иконок это потребует.

Проверено на копии установщика (другой AppId, папка и значение автозапуска, чтобы не трогать настоящий KeyMorph): старый
ярлык с иконкой `shell32.dll,3` после установки получил иконку `IbaKeyMorph.exe,0`; значение автозапуска, указывавшее на
`C:\old\elsewhere`, переписано на установленный exe; после удаления каталог программы пуст, ярлык установщика и значения
автозапуска удалены. Установщик собран Inno Setup 7; в CI используется Inno Setup 6 — использованы только общие функции
Pascal Script.

### Как проверить вручную (Windows)

1. Установите новую версию поверх старой (не удаляя): меню «Пуск» → IBA KeyMorph — новая иконка; в
   «Параметры → Приложения → Установленные приложения» у IBA KeyMorph новая иконка.
2. Если на рабочем столе/панели задач есть свой ярлык — его иконка тоже должна смениться (панель задач иногда
   показывает новую иконку после перезапуска Проводника: Диспетчер задач → «Проводник» → «Перезапустить»).
3. `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run` — значение `IBA KeyMorph` (если автозапуск включён)
   ведёт на `%LOCALAPPDATA%\Programs\IBA KeyMorph\IbaKeyMorph.exe`.
4. Удалите программу через «Параметры»: в `Run` значения `IBA KeyMorph` не остаётся, папки программы нет.
5. Крайний случай, если Проводник упорствует: `ie4uinit.exe -show` (Windows 10/11) или перезапуск Проводника.

## macOS

Каталог выдаёт **ZIP с приложением**: Publisher проверяет, что внутри ровно один `IBA KeyMorph.app` с bundle id
`com.iba.keymorph`, поэтому ни скрипт, ни pkg в архив добавить нельзя. Установка — это перетаскивание в «Программы»;
замену делает Finder («Заменить»), и только если старое приложение закрыто и называется так же.

Почему остаётся старое:

1. **Другая копия**: распаковка в «Загрузки» несколько раз даёт `IBA KeyMorph 2.app`; перетаскивание «Оставить оба»;
   приложение, запущенное из «Загрузок»/с рабочего стола. Все они известны Launch Services, у них один bundle id,
   и macOS может показать любую.
2. **Приложение не закрыто** (у него нет окна и Dock-значка, только текст EN/RU в строке меню): Finder не может заменить
   работающее приложение или заменяет, а работает старый процесс.
3. **Кеш значков** (Finder, Dock, Launchpad, `iconservices`) не обновляется, пока macOS не перерегистрирует бандл.
4. Номер сборки (`CFBundleVersion`) растёт с каждой сборкой Publisher — кеш определяется им; `AppIcon.icns` собирается
   `build-app.sh` из `assets/icon-macos-1024.png` во всех размерах (16, 32, 128, 256, 512 и @2x до 1024) — набор полный.

Что сделано:

- **`macos/scripts/update-keymorph.sh`** — чистая замена одной командой: закрывает программу; находит все копии с
  `com.iba.keymorph` (Spotlight, Launch Services, имена `*KeyMorph*.app` в «Программах», «Загрузках», на рабочем столе)
  и переносит их **в Корзину**; ставит новую через `ditto` (подпись и билет нотаризации сохраняются); `touch`,
  `lsregister -f -R`, по `--refresh-dock` перезапускает Dock и Finder; запускает программу. `--dry-run` только
  показывает действия. Настройки и журнал не трогает. Скрипт публикуется рядом с описанием программы в магазине
  (в ZIP его положить нельзя). **На Mac он не запускался** (Mac был недоступен), проверен только `bash -n`.
- **Само приложение** (`LaunchServicesRefresh`, `SystemIntegration.swift`): при первом запуске новой версии вызывает
  `lsregister -f` для своего бандла и обновляет его дату изменения (так Finder и Dock перечитывают иконку); если
  macOS знает несколько копий, пишет их список в журнал. Ничего не удаляет. **Не собиралось** (Swift собирается на Mac).
- Строка меню — текст `EN`/`RU` (системный цвет, адаптируется к светлой и тёмной теме); картинки-шаблона там нет, так
  что менять там нечего. Если новая система иконок даст монохромный глиф, его надо будет добавить как `NSImage` с
  `isTemplate = true`.

Вариант на будущее: pkg с `preinstall` (закрыть программу, убрать копии по bundle id) и `postinstall` (`lsregister`).
Для него нужны сертификат Developer ID Installer и правка проверок `keymorph_engine.py`/`site_publish.py`; без этого
в каталог такой файл не попадёт, поэтому пока выбран скрипт.

### Как проверить вручную (macOS)

1. До обновления: `mdfind "kMDItemCFBundleIdentifier == 'com.iba.keymorph'"` — список копий; `ls /Applications | grep -i keymorph`.
2. `./update-keymorph.sh --dry-run ~/Downloads/IBA-KeyMorph-<версия>-macOS.zip` — что будет перенесено и установлено.
3. Без `--dry-run`: в «Программах» остаётся один `IBA KeyMorph.app`, старые копии лежат в Корзине; в Finder, Launchpad и
   Dock (если закреплён) — новая иконка; `mdfind` из п. 1 показывает одну копию (+ Корзину).
4. `codesign --verify --deep --strict "/Applications/IBA KeyMorph.app"`; `spctl -a -vv "/Applications/IBA KeyMorph.app"` —
   `accepted … Notarized Developer ID`.
5. В журнале (`~/Library/Logs/IBA KeyMorph/keymorph.log`) после первого запуска: строка `Registered … with Launch Services`;
   при нескольких копиях — `Several copies of IBA KeyMorph are known to macOS`.
6. Если иконка в Dock всё ещё старая: снимите значок из Dock и перетащите заново; `--refresh-dock`; выход из системы и вход.
   Последняя мера (нужны права администратора): `sudo rm -rf /Library/Caches/com.apple.iconservices.store`,
   `killall Dock Finder`, перезагрузка.
7. «Универсальный доступ» после обновления: нажать «Выдать доступ…» в окне программы (известная особенность
   ad-hoc/обновлённых подписей описана в README).
